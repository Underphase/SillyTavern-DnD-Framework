# SillyTavern · D&D Framework

Автор: **Underphase**. Расширение для **SillyTavern 1.18.0**: свободные правила ролевой игры, память текущего чата, персонажи, настраиваемые треккеры и броски кубиков через function calling.

## Формы и подготовка истории (0.3.0)

Интерфейс снова на русском. В редакторе персонажа доступны обычные поля: имя, уровень, накопленный опыт и порог следующего уровня, здоровье, характеристики, личность, навыки и вещи. Вложенные свойства и списки можно добавлять и удалять кнопками. JSON оставлен отдельным дополнительным режимом; хранение по-прежнему структурированное, чтобы надёжно считать проверки.

При открытии нового чата с нулём или одним сообщением предлагается настроить персонажа до обработки памяти. **Настроить персонажа** открывает форму; **Пропустить** продолжает без неё. Уровень и опыт передаются ИИ как подтверждённые стартовые данные. Флажок **Сделать главным героем** необязателен; роль пользователя сама по себе не назначает ГГ. Отмена формы позволяет вернуться к предложению и пропустить его.

Опыт показан как `текущий / порог`, с полосой и оставшимся количеством. Порог — накопленный опыт следующего уровня, его задаёт пользователь или установленные правила мира. Для нового персонажа первого уровня начальный пример — 300; у старых персонажей без порога он не выдумывается. Значение 0 означает «не задан». Автоматического повышения уровня или сброса опыта нет.

Мастерская начинается с одного показателя. Можно выбрать шаблон **Шкала / Счётчик / Список / Заметка**, изменить название, вид, пример и правило обработки. Есть отдельное правило для каждого показателя; обработчик получает только правила полей с источником ИИ. Автоматическое оформление собирает интерфейс из виджетов. HTML, CSS и ID находятся в дополнительном разделе. Режим создания с ИИ формирует черновик: сначала проверка примера, затем сохранение. Примерные данные не становятся состоянием истории.

В настройках промптов добавлены **Скрытые проверки и кубики**. ИИ должна вызвать `rpg_check` до разрешения значимого неопределённого действия; броски — служебная информация рассказчика. Персонажи видят только события и последствия, не кубики, сложность или результаты инструментов. Выполнение инструкции зависит от основной модели и включённого function calling; код не может надёжно распознать любую ситуацию, где модель пропустила нужную проверку.

При пересмотре интерфейса изучены описание и модульные инструкции [Multihog D&D Framework](https://github.com/MultihogAurelius/SillyTavern-MultihogDnDFramework). Автор перевёл расширение в режим сопровождения. Здесь использован подход с отдельными правилами треккеров, но код и промпты реализованы самостоятельно.

## Примеры для обработчика (0.2.3)

В каждый запрос обработки памяти добавлены четыре коротких примера JSON: новый персонаж, изменение HP и лидера отряда, изменение навыка с сохранением остальных навыков и пустой ответ при отсутствии изменений. Это только примеры формата, а не факты истории. Они дополняют и сохранённые пользовательские промпты без сброса настроек. В основное повествование эти примеры не добавляются; дополнительных запросов к ИИ нет. Входной запрос обработчика становится немного длиннее.

Правила отдельно подчёркивают: `description` и `background` — строки; `personality`, `skills` и остальные перечисленные структурированные поля — объекты. Переход с PostgreSQL не меняет требуемые типы данных.

## Статус и время (0.2.2)

Нижняя строка показывает текущий этап: подготовка, ожидание ИИ, чтение ответа, проверка и сохранение. Во время работы виден счётчик секунд; после 30 секунд появляется пометка об ожидании. Зелёный означает успех, красный — ошибку, жёлтый — работу, предупреждение или отмену. Статус сохраняется при перерисовке окна; завершённые и отменённые операции не оставляют индикатор занятым. Повторные обработчики одной ошибки не дублируют её в журнале.

Dev и экспорт отчёта показывают местные дату и время в 24-часовом формате с UTC-смещением. Исходные ISO timestamps сохранены в полях `atUtc`/`exportedAtUtc`; старые записи только с часами остаются без придуманной даты. Отчёт также включает текущий статус.

Исправлен подтверждённый отчётом случай `description: {"description":"text"}`: одиночная обёртка преобразуется в строку без потери текста. Аналогичное преобразование поддерживается для background. Объекты с дополнительными свойствами не обрезаются молча.

## Диагностика ошибок

Интерфейс расширения на русском; язык истории и сохранённых персонажей не меняется. При ошибках памяти открой **Настройки → Dev mode → Сохранить настройки**, повтори обновление и открой **Dev → Копировать отчёт**. Кнопка **Скачать отчёт** сохраняет тот же отчёт в JSON. Если браузер телефона блокирует буфер обмена, появится выделяемое поле для ручного копирования.

Отчёт включает версию, модель (или режим профиля ST), этап сбоя, HTTP-статус при наличии, время, лимит выхода, usage, сообщение, стек и цепочку причин. В Dev mode добавляются фрагменты ответа провайдера и текста модели (до 24000 символов каждый, с отметкой об обрезке). Полная история и ключи из настроек в отчёт не добавляются; фрагменты ответа могут содержать текст РП. Ошибки сохраняются и при выключенном Dev mode, но без этих подробных фрагментов. Уже произошедший сбой нельзя восстановить задним числом полностью.

Исправлены тайм-аут запросов при фоновой обработке и приём частичных изменений отряда без потери остальных данных. Автоматических платных повторов запросов не добавлено. Ошибка формата не записывает частичный ответ ИИ как состояние истории.

## Установка и запуск

В SillyTavern открой **Extensions → Install extension** и вставь:

```text
https://github.com/Underphase/SillyTavern-DnD-Framework
```

Перезагрузи страницу. Лунную кнопку **☾** можно перетаскивать; нажатие открывает окно по центру экрана. Поддерживаются телефон и компьютер. Сборка и серверные плагины не нужны.

**Начиная с 0.2.0, RPG API, PostgreSQL и платный хостинг не нужны.** Персонажи, память, треккеры и журнал проверок сохраняются в метаданных текущего чата средствами SillyTavern. Если ST работает в Termux на телефоне, данные сохраняет этот экземпляр ST.

1. Открой чат и **☾ → Настройки**.
2. Настрой **Отдельная ИИ**: собственный OpenAI-совместимый endpoint, ключ и модель либо профиль подключения SillyTavern. Для провайдеров, запрещающих браузерные запросы, используй профиль ST.
3. Сохрани настройки и нажми **↻ Обновить**. После ответов память и персонажи обновляются автоматически.
4. Для кубиков включи **Enable function calling** в основном подключении ST и выбери модель с поддержкой инструментов.

ИИ по-прежнему требует своего подключения и оплачивается у выбранного провайдера. Локальные кубики, хранение, поиск моделей и оформление карточек не вызывают ИИ.

### Обновление с версии, использующей RPG API

Обнови расширение и перезагрузи ST. Уже загруженные персонажи, их ID, выбранный герой, память и сохранённые результаты остаются в текущем чате. Незавершённое обновление применяется локально. Автоматических обращений к старому RPG API больше нет.

Персонажи, находящиеся только в старой базе и ещё не загруженные в чат, не могут появиться без переноса. Для них оставлен ручной импорт: настрой **Optional: import from the old RPG API**, затем во вкладке **Персонажи** введи `owner_id`. Он создаёт отдельную локальную копию. Дальнейшие изменения не отправляются обратно в API. Сам репозиторий и база DnD API не изменяются.

Сохраняй резервные копии данных SillyTavern: теперь они содержат и состояние RPG. Локальный журнал не является независимым серверным аудитом. Одновременная игра в одном чате из нескольких вкладок не предусматривает слияния изменений.

### Выбор модели

В **Настройки → Отдельная ИИ** нажми **OpenRouter** либо введи адрес своего провайдера и нажми **Загрузить модели**. Прокручиваемый список поддерживает поиск по названию и ID. Название можно ввести вручную. В режиме профиля модель берётся из профиля ST.

## Повествование и проверки

Главный герой выбирается один: персонаж, пользователь или имя бота вручную. ИИ может предложить кандидата, выбор применяется после подтверждения. Пользователь не назначается ГГ автоматически.

Фокус не меняет управление персонажами. Промпт задаёт ближайшее действие или короткий обмен репликами, без самостоятельного пропуска сцен и времени. Добавление карточки не означает вход персонажа в сцену. Правила редактируются в поле **Scene pacing and character control**. Пользовательские промпты сохраняются при обновлении.

Основная модель вызывает `rpg_check`, код расширения вычисляет результат и сохраняет его перед возвратом модели:

- случайность — `crypto.getRandomValues` с отбрасыванием значений, устраняющим смещение при делении; без `Math.random`;
- формулы от 1 до 100 кубиков с 2–10000 гранями, преимущество/помеха для `1d20`;
- сложность с обоснованием либо сохранённая сложность цели;
- бонусы из записанных характеристик и навыков, сравнение `>=` или `<=`;
- автоматический успех только при сохранённом пассивном навыке, явно покрывающем действие;
- повтор в том же событии с тем же персонажем и `check_key` возвращает исходную запись, даже при изменении параметров;
- полный локальный журнал сохраняется, интерфейс и контекст используют последние записи.

Пассивный навык, например:

```json
{"skills":{"divine_locksmith":{"automatic_success":true,"actions":["open:astral_gate"]}}}
```

Для него используются `resolution="automatic"`, `passive_path="skills.divine_locksmith"` и `check_key="open:astral_gate"`. Невозможное действие задаётся `resolution="impossible"` с причиной. Сила персонажа не ограничена редакцией D&D.

Случайное число выбирает код, но необходимость броска, смысл действия и обоснованность начальной сложности всё ещё зависят от модели. Новый `check_key` технически означает другую проверку. Локальные данные можно изменить вручную; это защита от выбора результата моделью, а не от владельца устройства. При недоступном function calling расширение просит оставить проверки нерешёнными, а не выдумывать броски.

## Память и интерфейс

Новый чат получает отдельное состояние, в том числе при ответвлении с копией метаданных. Параметры подключения ИИ общие; выбор героя, персонажи, память и треккеры относятся к чату. Шаблон секций и треккеров можно сохранить для будущих чатов.

Обработчик получает изменения сообщений, сводку, подходящие факты и данные нужных персонажей. Полная история не пересылается на каждом ответе. `rpg_recall` возвращает дополнительные факты или полную карточку по запросу основной модели. Важные факты можно закрепить во вкладке **Память**.

Редактирование, удаление и смена варианта сообщения передаются обработчику для согласования состояния. Это исправление ИИ, а не механический откат. Хранятся текущее и предыдущее состояния. Устаревший ответ после смены чата отбрасывается.

Навыки и способности показаны компактными лунными карточками: описание, бонусы, стоимость и перезарядка. Остальные свойства доступны через **Подробнее**. Секции персонажа можно отключать по отдельности. **Dev mode** показывает ошибки, длительность запросов и расход токенов, если провайдер возвращает его.

## Свои интерфейсы

В **Мастерская** можно описать механику ИИ или самостоятельно редактировать промпт, HTML, CSS и определения полей. Нажатие **Создать с ИИ** создаёт черновик. Сохранение происходит отдельно; **Отмена** не меняет активный треккер.

В HTML используются `{{field_id}}`. Доступны виджеты:

| `type` | Представление |
|---|---|
| `text` | Текст |
| `number` | Число |
| `meter` | Значение и шкала до `max` |
| `inventory` | Список предметов |
| `coins` / `gems` | Монеты / кристаллы |
| `boolean` | Да / нет |

Источники `ai`, `character`, `scene`, `turns`, `clock` определяют обновление. `character` и `scene` используют `path`, например `current_hp` или `party.name`. `character` связан с выбранным персонажем API либо первым персонажем. `turns` — число обработанных ответов, `clock` — местное время устройства, которое обновляется при открытом интерфейсе. Эти источники не требуют отдельных запросов ИИ. Игровое время в сцене отличается от часов устройства.

Предпросмотр отображает вымышленные `value` из определения поля. Они **не записываются** как реальные данные чата. Свои стили и HTML работают в изолированном iframe с CSP: JavaScript, внешние ресурсы и доступ к интерфейсу ST запрещены. Это конструктор представлений и декларативных источников, а не выполнение произвольного сгенерированного кода.

## Разработка и проверки

```sh
node --test tests/*.test.js
```

Браузерный сценарий: `node tests/browser.mjs` с переменными `PLAYWRIGHT_MODULE` и при необходимости `BROWSER_CHANNEL`. Проверяются мобильное окно, карточки, конструктор, обновление ИИ, локальные кубики при недоступном API, повтор проверок, сохранение и изоляция чатов.

Изучен [Multihog D&D Framework](https://github.com/MultihogAurelius/SillyTavern-MultihogDnDFramework) как пример организации расширения. Код, стили и промпты примера не перенесены.
